# وشە | WUSHA

**A daily word-guessing game in Central Kurdish (Sorani).** Guess the hidden five-letter Kurdish word in six tries. Fully right-to-left, mobile-first, works offline, no account, no tracking.

> **یاریی ڕۆژانەی دۆزینەوەی وشەی کوردی.** وشە شاراوەکە لە شەش هەوڵدا بدۆزەرەوە.

---

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 72 unit + integration tests
npm run build      # type-check + production build → dist/
npm run preview    # serve the production build (service worker active)
```

Requires Node.js ≥ 20.

## Features

| Area | What you get |
|---|---|
| **Gameplay** | 6 × 5 grid, two-pass scoring (correct handling of repeated letters), dictionary validation, shake + Kurdish error messages, animated flip reveal, win bounce + confetti |
| **Daily mode** | Same word for everyone, chosen from a frozen, versioned list; resets at midnight **Asia/Baghdad**; progress saved; cannot be replayed once finished; live countdown |
| **Unlimited mode** | Endless rounds avoiding recent words; replay button; confirmation before abandoning a round (counts as a loss); separate statistics |
| **Kurdish language** | Full Sorani UI, `lang="ckb" dir="rtl"`, Noto Sans Arabic (bundled, offline), Eastern-Arabic numerals, Unicode normalization, grapheme-based letter counting |
| **Input** | On-screen Sorani keyboard (all 33 letters), physical Kurdish keyboards, optional Latin→Kurdish mapping (Central Kurdish layout), paste support, Tab/arrow-key navigation |
| **Statistics** | Played, wins, win %, current & best streak, guess distribution, daily history — Daily and Unlimited tracked separately |
| **Sharing** | Native share sheet, WhatsApp, Telegram, Facebook (when a site URL is set), copy-to-clipboard fallback. The answer is never included |
| **Settings** | Light / dark / system theme, sound, animations, colour-blind high-contrast palette, Latin key mapping, language selector (ready for more languages), reset data |
| **Archive** | Play any past daily puzzle; results are kept separately and never affect statistics |
| **Hard mode** | Revealed letters must be reused (greens in place); can be turned on only before a round starts |
| **Hints** | Unlimited mode: reveal up to 2 letters per round (never the last unknown one); marked 💡 in shares |
| **Share image** | 1080×1350 result card (logo, flag, coloured grid, score) via the share sheet or download — no letters revealed |
| **Report a word** | Players can suggest missing words or flag wrong words/definitions — opens their email (`VITE_REPORT_EMAIL`) or a pre-filled GitHub issue |
| **Extras** | First-run onboarding tutorial, 10 achievements, install-app button (Android/desktop prompt, iOS instructions), PWA offline mode, Kurdistan flag, respects `prefers-reduced-motion` |

## Architecture

```
src/
├── game/                 Pure, framework-free logic (fully unit-tested)
│   ├── kurdish.ts        Normalization, grapheme splitting, Sorani alphabet, Latin key map
│   ├── evaluate.ts       Two-pass scoring + keyboard colour priority
│   ├── engine.ts         Immutable game state: type / delete / paste / submit
│   ├── daily.ts          Asia/Baghdad calendar, puzzle number, countdown
│   ├── stats.ts          Daily & Unlimited statistics, streaks, history
│   ├── share.ts          Emoji grid (RTL-safe), share links, clipboard fallback
│   └── achievements.ts   Lightweight achievements
├── data/                 Dictionary (see below)
├── hooks/
│   ├── useGameStore.ts   App state: both modes, persistence, reveal timing, rollover
│   └── useSettings.ts    Settings, theme, reduced-motion detection
├── components/           Board, Keyboard, Header/ModeBar, modals, share panel, toasts, confetti
├── i18n/ckb.ts           Every UI string (typed — add a language by copying this file)
├── lib/                  localStorage wrapper (never throws), Web-Audio sound effects
└── styles/index.css      Design tokens (light/dark/high-contrast), tile & key animations
```

**State** lives in one hook (`useGameStore`) built on pure functions from `src/game/`. Every state update is functional, so fast key bursts are never lost, and nothing has side effects inside updaters (safe under React StrictMode). Everything is persisted to `localStorage` under the `wusha:v1:` prefix.

**No runtime dependencies** besides React and the bundled font. Sound is synthesized with Web Audio; confetti is a small canvas routine; the service worker is generated by a 20-line Vite plugin.

### How the Kurdish text handling works

* **Normalization** (`normalizeKurdish`) merges only *encodings of the same letter*:
  `ي ى → ی`, `ك → ک`, `ھ ہ → ه`, `ة ۀ → ە`, `أ إ آ → ا`, Arabic presentation forms via NFKC, and decomposed `ر + ◌ٚ → ڕ` etc. It strips harakat, tatweel, ZWNJ and bidi controls.
* It **never** merges distinct Kurdish sounds: `ر/ڕ`, `ل/ڵ`, `و/ۆ`, `ی/ێ`, `ه/ە`, `ک/گ`, `ف/ڤ` (tested).
* **Letters are grapheme clusters** (`Intl.Segmenter`), never `string.length`. The long vowel `وو` is two letters and fills two tiles, matching how it is written.
* **RTL**: rows use `dir="rtl"` so the first letter is the right-most tile; flips run right→left. The on-screen keyboard mirrors the physical *Central Kurdish* layout (q→ق, w→و, e→ە…). Numbers and Latin text are isolated with `<bdi>` / `unicode-bidi: isolate`.
* **Shared results**: each emoji row is reversed and wrapped in LEFT-TO-RIGHT MARKs, so under the Unicode Bidi Algorithm it renders exactly like the on-screen board in both RTL and LTR apps.

## The dictionary

```
src/data/
├── schema.ts      Entry type: word, normalized, letters, length, definition, category, status
├── answers.ts     Possible answers (with Kurdish definitions)          — collection 1
├── guesses.ts     Extra accepted guesses (never chosen as answers)     — collection 2
├── daily.ts       Frozen, versioned daily order + epoch (2026-01-01) + time zone
└── dictionary.ts  Builds lookup indexes; DICTIONARY_MODE switch
```

### ⚠️ Current status: demonstration dictionary

The bundled list contains **366 answers** (a full year of daily puzzles) **+ about 140 extra guesses**, including words from a contributed word list — common, everyday Sorani words in standard orthography, each with a short Kurdish definition and an English gloss for reviewers. **None has yet been reviewed by a native speaker**, so every entry is `status: 'unreviewed'`, the dictionary runs in `DICTIONARY_MODE = 'demo'`, and the Settings screen shows a clear "demo dictionary" notice to players.

Because the accepted-guess list is small, many real Kurdish words will be rejected as "not in the dictionary" until it is expanded. This is the biggest thing to address before a public launch.

### Going to production

1. Have a native Sorani speaker (ideally with a reference such as Hejar's *Hanbane Borîne* or the Kurdish Academy spelling rules) review `answers.ts` and `guesses.ts`.
2. Mark approved entries `status: 'verified'`; mark bad ones `'rejected'` (kept so they are never re-added).
3. Expand `guesses.ts` substantially (thousands of 5-letter words) — guesses do not need definitions.
4. When there are enough verified answers (≥ 365 recommended), set `DICTIONARY_MODE = 'production'` in `src/data/dictionary.ts`. Only `verified` words can then be answers; the demo notice disappears.
5. Run `npm run dict:check`. It fails if any word is not exactly 5 Sorani letters, is not in canonical form, is duplicated, lacks a definition (answers), uses a letter missing from the keyboard, or if a daily word is not an answer.

### Changing the daily list safely

The schedule in `src/data/daily.ts` is a list of frozen **eras**. Puzzle *N* uses the last era whose `fromPuzzle ≤ N`, at index `(N − fromPuzzle) mod length`. Era 1 (the original 157 words) runs until puzzle #334; era 2 (366 words) starts at #335 = 2026‑12‑01.

To change the list: **never edit an era that has started**. Add a new era whose `fromPuzzle` is a few days in the future and bump `DAILY_LIST_VERSION`. That way no player's word changes in the middle of a day, whenever the update is deployed.

## Deployment

The build is a static site in `dist/` with relative asset paths, so it works at a domain root or any sub-path.

**Optional build settings** (see `.env.example`; on GitHub add them as repository variables):
- `VITE_SITE_URL`: appended to shared results; enables the Facebook button.
- `VITE_REPORT_EMAIL`: where "report a word" messages go. Without it, reports open a pre-filled GitHub issue (players need a GitHub account).

### GitHub Pages (workflow included)
1. Repository **Settings → Pages → Source: GitHub Actions**.
2. Push to `main`/`master`. `.github/workflows/deploy.yml` installs, runs the tests, builds and publishes.
3. Optionally add a repository variable `SITE_URL` (Settings → Secrets and variables → Actions → Variables).

### Netlify / Vercel / Cloudflare Pages
Build command `npm run build`, output directory `dist`. No server configuration needed (single page, no routing).

### Any static host
`npm run build` and upload the contents of `dist/`. Serve over HTTPS so the service worker (offline mode) and the native share sheet work.

## Testing and verification status

**Automated (`npm test`, 72 tests, all passing):**
- Unicode normalization (Arabic/Persian variants, presentation forms, decomposed letters, invisible characters) and that distinct Kurdish letters are never merged
- Grapheme counting (`وو`, combining marks, emoji)
- Two-pass evaluation incl. repeated letters, green-over-yellow precedence, `وو` answers, keyboard colour priority
- Dictionary integrity (length, canonical form, duplicates, definitions, keyboard coverage, daily list ⊂ answers, production-mode rule)
- Game rules (max length, short/unknown words, win, loss after six, input blocked after finishing, Arabic-keyboard input)
- Daily logic in Asia/Baghdad (epoch, midnight boundary at 21:00 UTC, determinism, countdown)
- Statistics (idempotent recording, streaks, missed days, separate modes, corrupt storage), achievements
- Share text (format, answer never revealed, RTL row mirroring)
- React integration: RTL board order, full daily game via physical keyboard, stats persistence, no replay after reload, paste, Latin key mapping, burst typing

**Checked manually in headless Chromium (Playwright):** layouts at 320×568, 375×667, iPhone 14, Pixel 7 and 1280×800 — no horizontal scroll, board centred; light & dark themes; onboarding; invalid-word error; flip reveal order; win celebration and result sheet; loss in Unlimited; abandon-round confirmation; statistics and settings screens; offline reload through the service worker; no console errors.

**Not yet tested:** real iOS Safari and Android Chrome devices (only emulated), the native share sheet and WhatsApp/Telegram/Facebook deep links on real phones, physical Kurdish keyboard layouts on Windows/macOS (simulated with `keydown` events), screen readers (ARIA labels are present but unaudited), sound effects (they require a user gesture and real audio output), and the GitHub Actions workflow (not yet run).
